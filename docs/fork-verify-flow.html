1 在 GitHub 上 Fork 仓库 必须

浏览器打开 https://github.com/chenhg5/cc-connect，点击右上角 Fork 按钮。Fork 完成后你的仓库地址为：

bash — 添加 fork remote（仅首次）
$ git remote add fork git@github.com:game1991/cc-connect.git # 确认 remote $ git remote -v origin https://github.com/chenhg5/cc-connect.git (上游) fork git@github.com:game1991/cc-connect.git (你的 fork)
✓ 命名约定：origin 保留为上游，fork 指向你的仓库。这样既能 push fork，又能 git pull origin main 同步上游变更。
2 修改版本号 → 提交 → 打 Tag → Push 关键

将 Makefile 中的 VERSION 改为 fork 专用版本号。CI 会在 tag push 时自动构建全平台二进制、创建 GitHub Release、发布 npm 包。

bash — 一条龙完成
# ═══ 1. 修改版本号 ═══ # 编辑 Makefile，将 VERSION 递增 VERSION := v1.3.3-fork.4 # fork.1 → fork.2 → fork.3 ... # ═══ 2. 提交 + 打 Tag + Push ═══ $ git add -A && \ git commit -m "chore: bump version to v1.3.3-fork.4" $ git tag v1.3.3-fork.4 $ git push fork feat/role-based-tool-permissions --tags # ═══ 3. CI 自动执行（约 7 分钟） ═══ # ✅ 构建 6 平台二进制 (linux/darwin/windows × amd64/arm64) # ✅ 创建 GitHub Release + 上传产物 + checksums # ✅ 发布 npm 包 @game1991/cc-connect 到 GitHub Packages # # 监控进度： $ gh run list --repo game1991/cc-connect --limit 1 $ gh run watch <run-id> --repo game1991/cc-connect
⚠ 版本号规则：使用 vX.Y.Z-fork.N 格式。run.js 会比较 bin/cc-connect.exe 的输出与 package.json 中的版本号。如果 fork 版本号 ≥ 官方版本号，就不会触发自动重装覆盖你的二进制。CI 会自动将 npm package.json 版本同步为 tag 版本。
3 配置 npm 仓库 + 安装 Fork 版本 必须

GitHub Packages 需要认证。每个团队成员需一次性配置 ~/.npmrc，之后一条命令即可安装。

bash — 首次：配置 ~/.npmrc（Windows + MSYS2 软连接方案）
# npm (Windows 原生) 读取 C:\Users\<you>\.npmrc # MSYS2 终端读取 /home/<you>/.npmrc（即 D:\msys64\home\KC\.npmrc） # 两个路径不同步 → 配一个忘一个 → 安装失败 # 解决方案：MSYS2 的 .npmrc 软连接到 Windows 的，一劳永逸 # 1. 写入 Windows 用户目录下的 .npmrc $ cat > /c/Users/KC/.npmrc <<'EOF' @game1991:registry=https://npm.pkg.github.com //npm.pkg.github.com/:_authToken=YOUR_GITHUB_PAT EOF # 2. 删掉 MSYS2 的旧 .npmrc，创建软连接 $ rm -f ~/.npmrc $ ln -s /c/Users/KC/.npmrc ~/.npmrc # PAT 需要有 read:packages 权限 # 生成方式：GitHub → Settings → Developer settings → Personal access tokens → Fine-grained token
bash — 安装
$ npm install -g @game1991/cc-connect # postinstall 自动从 GitHub Release 下载对应平台的二进制 [cc-connect] Downloading from https://github.com/game1991/cc-connect/releases/download/v1.3.3-fork.4/... [cc-connect] Installed to D:\nodejs\node_global\node_modules\@game1991\cc-connect\bin\cc-connect.exe
✓ 一键安装：以后团队成员只需 npm install -g @game1991/cc-connect 即可安装最新 fork 版本

🗑 完全卸载 cc-connect

切换 fork 版本或重新安装前，建议执行完整清理，避免残留导致不可预期行为。以下按顺序执行：

bash — Step 1: 停止 daemon + 卸载计划任务
$ cc-connect daemon stop $ cc-connect daemon uninstall # 确认 schtasks 中已无条目 $ schtasks /query /tn "cc-connect" 2>&1 || echo "已清除"
bash — Step 2: 强制杀残留进程
# MSYS2 / Git Bash $ ps -W | grep -i cc-connect | grep -v grep | awk '{print $1}' | xargs -I{} taskkill /PID {} /F # 或管理员 PowerShell 中： # Get-Process cc-connect -ErrorAction SilentlyContinue | Stop-Process -Force
bash — Step 3: 卸载 npm 包（两条都执行，确保无残留）
$ npm uninstall -g @game1991/cc-connect $ npm uninstall -g cc-connect # 确认已清除 $ npm list -g --depth=0 | grep cc-connect #（无输出 = 已清除）
bash — Step 4: 清理用户数据目录（可选，重新安装可保留配置）
# 仅清理运行时数据（保留 config.toml） $ rm -rf ~/.cc-connect/logs/ ~/.cc-connect/run/ ~/.cc-connect/sessions/ $ rm -f ~/.cc-connect/daemon.json ~/.cc-connect/.config.toml.lock # 彻底清除（含配置，从零开始） $ rm -rf ~/.cc-connect/
⚠ 关键检查点：卸载完成后依次验证 — schtasks 无条目、ps -W 无进程、npm list -g 无 cc-connect、which cc-connect 找不到命令。全部通过才算干净。
⚠ 隐藏残留坑：npm 两个 prefix。如果你改过 npm config set prefix，新包装到自定义路径，但旧包可能还在默认路径 C:\Users\<you>\AppData\Roaming\npm\ 下。npm uninstall -g 只删当前 prefix 下的包，不会清理另一个。手动检查：ls "$APPDATA/npm/node_modules/" | grep cc-connect，如有残留直接 rm -rf。

常见问题排查

cp: Device or resource busy
cc-connect.exe 进程仍在运行并锁定了文件。执行 ps -W | grep cc-connect 找到 PID，在管理员终端执行 taskkill /PID <PID> /F。
daemon install 报 "config.toml not found"
当前二进制仍是上游旧版。确认 cc-connect --version 显示 fork commit 后重新安装 daemon。fork 版本已修复三级 fallback 自动写入 --config。
npm install 报 E403 Forbidden
GitHub Packages 需要 PAT 认证。确保 ~/.npmrc（Windows 用户目录下的）包含 //npm.pkg.github.com/:_authToken= 且 token 有 read:packages 权限。可用 gh auth refresh -h github.com -s read:packages 刷新权限。
npm 读的是哪个 .npmrc？
Windows 下 npm 读取 C:\Users\<you>\.npmrc，MSYS2 终端读取 D:\msys64\home\<you>\.npmrc，两个路径不同！建议将 MSYS2 的 ~/.npmrc 做软连接到 Windows 的：ln -s /c/Users/<you>/.npmrc ~/.npmrc。这样无论在哪个终端修改，两边始终同步。
taskkill 提示 Permission denied
需在管理员终端（右键 → 以管理员身份运行）执行。
CI tag push 后 npm 版本号不对
fork-release.yml 中有 "Sync package.json version to tag" 步骤，会自动将 npm package.json 版本同步为 git tag（去掉 v 前缀）。确保 tag 名与 Makefile VERSION 一致即可。
daemon status 显示 Queued 而非 Running
Windows schtasks AtLogOn 触发器在开机后不会立即运行，而是排队等待下次登录。手动运行 launcher 脚本即可：powershell -File ~/.cc-connect/cc-connect-daemon.ps1
卸载后 AppData\Roaming\npm 下仍有 cc-connect 残留
npm 有两个全局 prefix：你当前配置的（npm config get prefix）和默认的 C:\Users\<you>\AppData\Roaming\npm。npm uninstall -g 只删当前 prefix 下的包，旧 prefix 下的残留需手动清理：rm -rf "$APPDATA/npm/node_modules/cc-connect" "$APPDATA/npm/cc-connect.ps1" "$APPDATA/npm/cc-connect.cmd"。如果 $APPDATA/npm/node_modules/ 已空，可整个删掉 rm -rf "$APPDATA/npm"。
daemon stop 停不掉进程
fork 版 daemon stop 已增加 PID 回退杀进程逻辑：schtasks/systemctl 失败时，读取 daemon.json 中的 ConfigFile → 定位 .lock 文件中的 PID → 验证进程映像名为 cc-connect → TerminateProcess/Kill。如仍失败，输出错误提示 cc-connect daemon restart --force。此场景通常发生在进程非 schtasks 启动或进程卡死时。
daemon restart --force 新进程启动报端口占用
旧版 --force Kill 进程后立即 Restart，旧进程可能尚未释放端口。fork 版在 Kill 成功后 sleep 500ms 等待资源释放。如果 500ms 不够（大型项目清理较慢），可先手动 daemon stop 等几秒再 daemon start。
daemon.json 路径是正斜杠，这正常吗？
正常。fork 版在 daemon install 保存 Meta 时对所有路径执行 filepath.ToSlash()，统一为正斜杠。Go 在 Windows 上同时接受 / 和 \，正斜杠更利于跨平台可移植（WSL、CI、SSH 等）。
workspace key 在 Windows 上不一致
上游 normalizeWorkspacePath 在 Windows 上返回反斜杠路径，导致同一目录不同写法的 workspace 无法命中同一条记录。fork 版已加 filepath.ToSlash，所有 workspace key 统一为正斜杠。
~ 路径缩写在 Windows 上不生效
上游 replyFooterHomeRelativePath 用反斜杠做前缀比较，Windows 上 filepath.Clean 会把 / 转 \，导致 strings.HasPrefix(path, home + "/") 永远为 false。fork 版统一用 filepath.ToSlash 后再比较。
daemon restart --force 用自定义 --config 时杀错进程
旧版 --force 用 WorkDir + "/config.toml" 硬编码构造 lock 文件路径，当 --config 指定非标准文件名时找错文件。fork 版改用 metaConfigPath() 从 daemon.json 读取 ConfigFile 字段，正确解析任意配置文件名。
