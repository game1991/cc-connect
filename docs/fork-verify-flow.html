1 编译 Fork 代码 必须

在 fork 仓库中编译出 Windows 二进制。build-noweb 跳过前端，速度最快；build 包含 Web Admin UI。

bash
# 进入 fork 仓库 $ cd /d/WorkSpace/src/cc-connect # 确认在正确分支 $ git branch --show-current feat/role-based-tool-permissions # 快速编译（跳过 Web 前端，推荐） $ make build-noweb # 或完整编译（需要 pnpm） $ make build
✓ 编译成功：项目根目录生成 cc-connect（无 .exe 后缀，但实际是 PE 二进制）
验证
$ ./cc-connect --version cc-connect v1.3.3-beta.4 commit: a4558147 ← 必须是你的 fork commit built: 2026-06-07T08:18:31Z $ file cc-connect PE32+ executable for MS Windows 6.01 (console), x86-64
2 定位 npm 安装的二进制路径 必须

npm 安装的 cc-connect 是三层 wrapper 架构，真正需要替换的是最底层的 Go 二进制。

$npm_root/cc-connect/ ├── bin/cc-connect.exe ← 真正的 Go 二进制（替换目标） ├── run.js ← Node.js wrapper，透传命令给 bin/cc-connect.exe ├── install.js ← 版本不匹配时自动重装 └── package.json ← 记录版本号 全局调用链： cc-connect xxx → shell wrapper → node run.js → bin/cc-connect.exe
bash
# 查看 npm 全局模块根目录 $ npm root -g D:\nodejs\node_global\node_modules # 确认目标二进制存在 $ ls -la "$(npm root -g)/cc-connect/bin/" -rwxr-xr-x 1 KC None 22723584 cc-connect.exe # 查看当前官方版本（替换前的基准） $ cc-connect --version cc-connect v1.3.3-beta.4 commit: d577db28 ← 上游 commit（非 fork）
3 停止并卸载旧 Daemon 必须

卸载 Windows 任务计划程序（schtasks）中的 cc-connect 任务，避免旧二进制开机自启。

bash
# 停止 daemon $ cc-connect daemon stop # 卸载 schtasks 计划任务 $ cc-connect daemon uninstall # 确认已卸载 $ cc-connect daemon status Status: Not installed Platform: schtasks
⚠ 如果 daemon uninstall 提示权限不足，需要在 管理员终端 执行 schtasks /Delete /TN "cc-connect" /F
4 确认旧进程已退出 关键

Windows 上运行中的 exe 文件被锁定，无法覆盖。必须确保所有 cc-connect.exe 进程都已终止。

bash
# MSYS2 环境下查看 Windows 进程 $ ps -W | grep -i cc-connect | grep -v grep # 如果有输出，在管理员终端执行（用实际 PID 替换）： # taskkill /PID 33724 /F
⚠ 这是最常见的卡点。如果 cp 报 Device or resource busy，说明还有进程在运行。
备选方案：用 cc-connect --force daemon status 强制杀旧进程并启动新实例（但会前台运行，需要再 Ctrl+C 停止）。
5 替换二进制文件 必须

用 fork 编译产物覆盖 npm 安装的 Go 二进制。注意 MINGW 编译产物无 .exe 后缀，但 cp 时必须指定 .exe。

bash
# 替换（注意：源文件无 .exe 后缀，目标必须加 .exe） $ cp /d/WorkSpace/src/cc-connect/cc-connect "$(npm root -g)/cc-connect/bin/cc-connect.exe" # 验证替换成功 $ "$(npm root -g)/cc-connect/bin/cc-connect.exe" --version cc-connect v1.3.3-beta.4 commit: a4558147 ← fork commit，替换成功 built: 2026-06-07T08:18:31Z
⚠ npm 更新会覆盖：以后执行 npm install -g cc-connect@beta 会重新下载官方二进制。升级后需重新执行此 cp 命令。
6 重新安装 Daemon 必须

用新二进制注册 Windows 任务计划程序，实现开机自启。Fork 修复后无需 --config 参数即可自动定位配置。

bash
$ cc-connect daemon install cc-connect daemon installed and started. Platform: schtasks Binary: D:\nodejs\node_global\node_modules\cc-connect\bin\cc-connect.exe WorkDir: C:\Users\KC\.cc-connect Log: C:\Users\KC\.cc-connect\logs\cc-connect.log LogMax: 10 MB
✓ 无需 --config：fork 修复后三级 fallback 自动生效（--config → WorkDir/config.toml → ~/.cc-connect/config.toml）
7 验收验证 关键

确认全局命令已是 fork 版本，daemon 正常运行，平台连接正常。

bash — 全流程验证

常见问题排查

cp: Device or resource busy
cc-connect.exe 进程仍运行锁定了文件。执行 ps -W | grep cc-connect 找到 PID，在管理员终端执行 taskkill /PID <PID> /F。
daemon install 报 "config.toml not found"
当前二进制仍是旧版（commit d577db28）。确认 cc-connect --version 显示 fork commit。如不是，重新执行 cp 替换步骤。
npm update 后版本回退
npm install -g cc-connect@beta 会覆盖你的 fork 二进制。升级后需重新执行 cp /d/WorkSpace/src/cc-connect/cc-connect "$(npm root -g)/cc-connect/bin/cc-connect.exe"。
taskkill 提示 Permission denied
需要在管理员终端（右键 → 以管理员身份运行）中执行 taskkill 命令。普通用户无权终止其他进程。
daemon status 显示 Not installed
schtasks 任务被意外删除。重新执行 cc-connect daemon install 即可。
