cc-connect 是什么

cc-connect 是 AI 编码 Agent 与即时通讯平台的桥接工具。用户在飞书、Telegram、Slack 等聊天窗口中即可操控 Claude Code、Codex、Gemini CLI 等 Agent，完成代码编写、文件读写、命令执行等任务。

核心价值：把 Agent 从终端搬到聊天窗口 — 不需要 SSH、不需要 IDE，在手机上也能让 AI 改代码。

角色权限系统
安全提示：未配置角色时，所有用户共享 agent 级权限策略，群聊中任何人回复"允许"即可批准工具请求。强烈建议为生产环境配置 admin/developer/readonly 三级角色。

不同用户拥有独立的权限策略，避免"实习生批准 admin 的危险命令"。

用户发消息
→
resolveUserRole()
→
mode + allowed_tools
→
yolo → 全部自动通过
default → 白名单自动，其余弹窗
dontAsk → 白名单自动，其余拒绝
→
权限回调
→
身份校验：仅发起者或 admin
配置示例
# config.toml
[[projects]]
name = "my-project"

[projects.agent]
type = "claudecode"

[projects.agent.options]
work_dir = "D:/WorkSpace/src/my-project"
mode = "default"               # agent 级默认值

[projects.users]
default_role = "readonly"      # 未匹配角色的用户

[projects.users.roles.admin]
user_ids = ["ou_admin_xxx"]    # /whoami 获取 ID
mode = "yolo"

[projects.users.roles.developer]
user_ids = ["ou_dev_aaa", "ou_dev_bbb"]
mode = "default"
allowed_tools = ["Read","Grep","Glob","Bash","Edit","Write"]

[projects.users.roles.readonly]
user_ids = ["*"]               # * 匹配所有未分配角色用户
mode = "dontAsk"
allowed_tools = ["Read","Grep","Glob"]
模式 × allowed_tools
allowed_tools 为空allowed_tools 有值工具不在白名单
yolo全部自动通过冗余仍自动通过
default全部弹窗确认白名单自动通过弹窗确认
dontAsk全部自动拒绝白名单自动通过自动拒绝
审批身份校验
发起者本人 — 可批准/拒绝
admin 角色 — 可批准/拒绝任何人的请求
其他人 — 回复"允许"会被拒绝

安装与部署
前置条件
依赖最低版本检查
Node.js + npm18+node --version
Git任意git --version
配置 npm 作用域

编辑 ~/.npmrc（Windows: C:\Users\<用户名>\.npmrc）： 

@game1991:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=<YOUR_GITHUB_PAT>

PAT 获取：GitHub → Settings → Developer settings → Personal access tokens → Fine-grained → read:packages

安装
npm install -g @game1991/cc-connect
cc-connect --version
创建配置
cc-connect                  # 首次运行自动生成模板
# 或手动创建
mkdir -p ~/.cc-connect
cp config.example.toml ~/.cc-connect/config.toml

最小飞书配置：

language = "zh"

[log]
level = "info"

[[projects]]
name = "my-project"

[projects.agent]
type = "claudecode"

[projects.agent.options]
work_dir = "D:/WorkSpace/src/my-project"
mode = "default"

[[projects.platforms]]
type = "feishu"

[projects.platforms.options]
app_id = "cli_xxxxxxxxxxxx"
app_secret = "xxxxxxxxxxxxxxxxxxxxxxxx"
启动
# 前台调试
cc-connect

# 后台 daemon
cc-connect daemon install
cc-connect daemon status
cc-connect daemon logs -f
Web 管理界面
cc-connect setup-web

或手动在 config.toml 中添加：

[bridge]
enabled = true
port = 9810
token = "<YOUR_BRIDGE_SECRET>"

[management]
enabled = true
port = 9820
token = "<YOUR_MANAGEMENT_SECRET>"

访问 http://localhost:9820，用 management token 登录。

运维命令
Daemon 管理
cc-connect daemon install       # 安装并启动
cc-connect daemon status
cc-connect daemon logs -f
cc-connect daemon stop
cc-connect daemon restart
cc-connect daemon restart --force  # 杀进程 → 500ms → 重启
cc-connect daemon uninstall
清理与重装
cc-connect clean             # 清运行时，保留 config/crons
cc-connect clean reset       # 全部删除，config/crons 先备份
cc-connect reinstall --yes   # 清理 + npm 重装 + 恢复 + daemon install
reinstall 两阶段：Phase 1（Go）备份+清理+卸载+生成脚本，Phase 2（脚本）npm 重装+恢复+daemon install。MINGW bash 一条命令完成；PowerShell/CMD 需两步执行。
升级
cc-connect daemon stop
npm update -g @game1991/cc-connect
cc-connect --version
cc-connect daemon restart
日志
cc-connect daemon logs          # 末尾日志
cc-connect daemon logs -f       # 实时跟踪
cc-connect daemon logs -n 100  # 最近 100 行

日志自动轮转（10MB），保留一份备份。

故障排查
daemon stop 停不掉 ▶ 
cc-connect daemon restart --force   # 杀进程 → 重启
ps -W | grep -i cc-connect
taskkill /PID <PID> /F
daemon stop 已含 PID 直杀回退。
daemon install 找不到配置文件 ▶
三级 fallback 自动查找：--config → WorkDir/config.toml → ~/.cc-connect/config.toml。也可显式传 --config。

版本与发布
版本号规则

格式：v<major>.<minor>.<patch>-fork.<N>
fork.N 独立于上游 -beta.N 递增。
⚠ 必须 fork.N ≥ 上游 npm beta 排序值，否则 run.js 会覆盖本地二进制。
版本号将在最终定版时确定。
